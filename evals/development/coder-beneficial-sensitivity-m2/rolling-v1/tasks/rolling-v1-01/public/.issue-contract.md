# Implement deterministic event session rollups

Only `eventrollup/rollup.py` and `eventrollup/__main__.py` are editable. Do not add paths. The following paths are protected and must remain byte-for-byte unchanged:

- `.issue-contract.md`
- `CODER.md`
- `README.md`
- `eventrollup/__init__.py`
- `eventrollup/formatting.py`
- `examples/events.ndjson`
- `tests/test_formatting.py`

All behavior below uses only the Python standard library. Non-string items in the `events` iterable and JSON objects containing duplicate keys are outside the scored contract.

## Scored requirements

PUBLIC-R1 — one-pass transformation and fresh result

Implement `eventrollup.rollup.rollup(events, idle_seconds)`. Consume `events` with exactly one iteration, without requiring a sequence or mutating the caller's object, and return a newly allocated list on every call. The scored one-pass vector wraps this single line in an iterable whose `__iter__` raises on a second call:

```json
{"user":"u","at":"2026-01-01T00:00:00Z","action":"open"}
```

The result for that vector is one session. Two independent calls with an empty list must return two distinct empty list objects.

PUBLIC-R2 — idle threshold validation

`idle_seconds` must be a positive `int`, with `bool` explicitly rejected. Each of `0`, `-1`, `True`, `False`, `1.5`, and `"60"` must raise `ValueError` whose exact text is:

```text
idle_seconds must be a positive integer
```

`1` is valid.

PUBLIC-R3 — blank physical lines

Ignore lines for which `line.strip()` is empty, including `""`, `"   "`, and `"\t"`. Blank lines still occupy physical line numbers used by later diagnostics.

PUBLIC-R4 — JSON event shape and physical-line error

Every nonblank line must decode as one JSON object with keys `user`, `at`, and `action`, and each of those three values must be a non-empty string. Extra object keys are permitted. Malformed JSON, a non-object JSON value, a missing required key, an empty required string, or a non-string required value must raise `ValueError` with exact text:

```text
line N: expected a JSON object with non-empty string user, at, and action
```

The scored physical-line vector places one valid event on line 1 and malformed JSON on line 2, so its exact message uses `line 2`. Separate scored vectors use an empty `action`, a missing `user`, and an integer `at`.

PUBLIC-R5 — real UTC whole-second timestamps

`at` must match exactly `YYYY-MM-DDTHH:MM:SSZ` using ASCII decimal digits and must name a real Gregorian calendar instant. Fractions, offsets, impossible dates, and other spellings are invalid. Each invalid timestamp raises `ValueError` with exact text:

```text
line N: at must be a real UTC whole-second timestamp
```

The invalid scored values are `2026-01-01 00:00:00Z`, `2026-01-01T00:00:00.1Z`, `2026-01-01T00:00:00+00:00`, and `2026-02-30T00:00:00Z`. The valid leap-day vector is `2024-02-29T23:59:59Z`.

PUBLIC-R6 — per-user chronological input

For each user independently, timestamps must be nondecreasing in input order. Equal timestamps are valid. Interleaving another user's events does not reset or change this check. A descending timestamp raises `ValueError` with exact text:

```text
line N: timestamps for user USER must be nondecreasing
```

The scored descending vector is user `u` at `2026-01-01T00:00:10Z`, user `v` at `2026-01-01T00:00:01Z`, then user `u` at `2026-01-01T00:00:09Z`; its exact diagnostic is `line 3: timestamps for user u must be nondecreasing`.

PUBLIC-R7 — session boundary

Maintain one active session per user. The user's first event begins a session. A later event begins a new session exactly when its gap from that user's previous event is greater than or equal to `idle_seconds`; a smaller gap remains in the active session. The scored boundary vectors use a 60-second threshold and gaps of exactly 60 seconds and 59 seconds.

PUBLIC-R8 — exact session values and action counts

Every returned session must be a plain dictionary with exactly these four keys and meanings:

- `user`: the preserved user string.
- `started_at`: the first event's original `at` string.
- `ended_at`: the last event's original `at` string.
- `actions`: a plain dictionary mapping each preserved action string to its integer occurrence count within the session.

The scored vector has one user at seconds 00, 10, and 20 with actions `view`, `view`, and ` deploy ` and a 60-second threshold. It must retain one session, count `view` as 2, preserve ` deploy ` exactly, use the first and last original timestamp strings, and expose no additional session keys.

PUBLIC-R9 — deterministic session ordering

Return sessions sorted ascending first by the `started_at` string and then by the `user` string. The scored vector encounters user `b` at second 00, user `a` at second 00, and user `b` again at minute 02 with a 60-second threshold. Its returned `(started_at, user)` order must be `(00:00:00Z, a)`, `(00:00:00Z, b)`, `(00:02:00Z, b)`.

PUBLIC-R10 — input selection and compact UTF-8 JSONL output

Implement `eventrollup.__main__.main(argv=None)` and `python -m eventrollup`. Accept `--idle-seconds INTEGER` with default `300`, plus zero or one positional path with default `-`. Both an omitted path and `-` read `sys.stdin`; any other path is opened as UTF-8 text. On success, serialize each session with the protected `eventrollup.formatting.compact_json`, append exactly one newline per session, write the complete JSONL to stdout, write nothing to stderr, and return status `0`.

The omitted-path and explicit-`-` scored input is:

```json
{"user":"zoë","at":"2026-01-01T00:00:00Z","action":"café"}
```

Its exact stdout is the following single UTF-8 line (with a trailing newline):

```json
{"actions":{"café":1},"ended_at":"2026-01-01T00:00:00Z","started_at":"2026-01-01T00:00:00Z","user":"zoë"}
```

The 300-second default is scored separately by supplying the two protected `examples/events.ndjson` lines through omitted-path stdin without `--idle-seconds`. Their 120-second gap must remain one session, with exact stdout:

```json
{"actions":{"edit":1,"view":1},"ended_at":"2026-01-01T00:02:00Z","started_at":"2026-01-01T00:00:00Z","user":"ada"}
```

The file-path scored vector is the protected `examples/events.ndjson` with `--idle-seconds 60`. Its exact two output lines are:

```json
{"actions":{"view":1},"ended_at":"2026-01-01T00:00:00Z","started_at":"2026-01-01T00:00:00Z","user":"ada"}
{"actions":{"edit":1},"ended_at":"2026-01-01T00:02:00Z","started_at":"2026-01-01T00:02:00Z","user":"ada"}
```

PUBLIC-R11 — buffered processing and exact operational errors

Do not write any session output until input processing and serialization have both completed. Catch file `OSError` and processing `ValueError`. On either, write no stdout, write exactly `error: MESSAGE\n` to stderr where `MESSAGE` is `str(caught_exception)`, and return status `2`.

One scored vector supplies a valid line followed by malformed JSON on physical line 2; it requires empty stdout and exact stderr `error: line 2: expected a JSON object with non-empty string user, at, and action\n`. The file-error vector passes a guaranteed-absent `.scored-missing-events.ndjson` path, derives `MESSAGE` by attempting to open that same path as UTF-8 text, and requires the exact same `str(OSError)` in stderr.

PUBLIC-G1 — protected compatibility behavior

The protected serializer must continue to satisfy `compact_json({"beta": "β", "alpha": 1}) == '{"alpha":1,"beta":"β"}'`, and `python -m unittest discover -s tests -v` must pass. All seven protected files listed at the top must remain byte-for-byte unchanged, `CODER.md` must remain zero bytes, and the public tree must contain exactly the nine listed public files (the two editable files plus the seven protected files), with no added paths.
