# Issue TRIAL-B: add a `stats` subcommand to logscan

logscan currently ships a single subcommand (`count`). This issue adds a second
subcommand, `stats`, that computes aggregate statistics for a log file.

## Primary requirement

`python -m logscan stats PATH` must:

1. Read the file at PATH and parse it with the same record rules used
   everywhere in logscan (see `logscan/parser.py`): a record is a line whose
   first space-separated token (after stripping leading/trailing whitespace)
   is one of `DEBUG`, `INFO`, `WARNING`, `ERROR` and which has a non-empty
   message after that token. Every other line is ignored.
2. Print a single JSON object to stdout. Any formatting/indentation is
   acceptable — the output is parsed with `json.loads`. The object must have
   exactly these four keys:
   - `"total"`: the number of parsed records (integer)
   - `"by_level"`: an object mapping each level that occurs to its record
     count (levels with zero records are omitted)
   - `"unique_messages"`: the number of distinct message strings (integer)
   - `"top_messages"`: a list of up to N distinct message strings, ordered by
     descending record count, with ties broken by ascending lexicographic
     (codepoint) order of the message string
3. Exit with code 0 on success.
4. Accept an optional `--top N` flag (integer) that sets the maximum length N
   of the `top_messages` list. The default for `--top` is 3.

The existing `count` subcommand and the existing tests in `tests/test_parser.py`
and `tests/test_cli.py` must keep working unchanged in behavior.

## Published checker probes (disclosure only)

This section adds no production requirement. It publishes the exact
evaluator-owned paths, file bytes, and expected values used to score the
requirements already stated above and in the tagged acceptance notes. Each
fixture is created in one evaluator-owned temporary directory; the directory's
absolute path is variable, but the following basenames are exact.

`basic.log` contains exactly these UTF-8 lines, including the displayed blank
line before `DEBUG zeta` and a final newline:

```text
INFO alpha
ERROR beta
INFO alpha
junk line
WARNING gamma delta
INFO omega

DEBUG zeta
```

Its scored projection is `total` 6, `by_level`
`{"DEBUG": 1, "ERROR": 1, "INFO": 3, "WARNING": 1}`, and
`unique_messages` 5. R1 does not score its `top_messages` value.

`ties.log` contains exactly these UTF-8 lines and a final newline:

```text
INFO bb
INFO aa
INFO bb
INFO cc
INFO aa
INFO dd
```

For this file, default `--top` must yield `["aa", "bb", "cc"]`,
`--top 2` must yield `["aa", "bb"]`, and `--top 10` must yield
`["aa", "bb", "cc", "dd"]`.

`empty.log` is a zero-byte file. `does-not-exist.log` is an absent path in the
same temporary directory; the exact runtime absolute path replaces `PATH` in
the already-published missing-file message.

For the missing-file probe, the already-published behavior is scored as exit
status 3, zero-byte stdout, and stderr consisting of that exact message plus
one final newline. The already-published version behavior is scored as exit
status 0, stdout exactly `logscan 1.3.0\n`, and zero-byte stderr.

`count.log` contains exactly these UTF-8 lines and a final newline:

```text
INFO a
nope
ERROR b
DEBUG c
```

The unchanged `count` command is scored with exit status 0, stdout exactly
`3\n`, and empty stderr for this file.
