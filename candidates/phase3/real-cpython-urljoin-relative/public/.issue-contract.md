# Issue: preserve relative bases in `urllib.parse.urljoin()`

`urljoin()` correctly resolves relative references against normal absolute
bases, but it drops information when the base itself is relative or has an
undefined or empty authority. This behavior is outside RFC 3986's absolute-base
model, but it is longstanding Python behavior relied upon by callers and must
remain supported.

## Requirements

1. The `urljoin()` function must preserve relative base paths and undefined or empty authority markers for the enumerated empty, slash-only, authority, scheme-only, rooted-path, and relative-path cases.
2. Add a runnable standard-library regression module at `tests/test_urljoin_relative.py` that covers both the undefined-authority `//` base and the relative-path `/b/c` base.

The required results are:

| base | reference | result |
| --- | --- | --- |
| `//` | `w` | `///w` |
| `//` | `/w` | `///w` |
| `//a` | `w` | `//a/w` |
| `http:` | `w` | `http:/w` |
| `http://` | `w` | `http:///w` |
| `http://a` | `w` | `http://a/w` |
| `/b/c` | `w` | `/b/w` |
| `///b/c` | `w` | `///b/w` |

For each base above, empty references, slash-only references, and explicit
authorities must retain the same component semantics demonstrated by the table.
Existing RFC-style absolute-base joins and parsing behavior must keep working.

Run the regression module directly with
`python3 tests/test_urljoin_relative.py` from the repository root.
