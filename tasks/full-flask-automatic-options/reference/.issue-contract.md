# Make explicit automatic `OPTIONS` enablement effective

Flask allows automatic `OPTIONS` responses to be controlled globally and by
the `provide_automatic_options` attribute on a view function or `View` class.
The explicit view controls currently behave asymmetrically: they can disable
automatic handling, but an explicit `True` does not restore it when
`PROVIDE_AUTOMATIC_OPTIONS` is disabled globally.

Correct route registration so explicit enablement is honored without changing
the default behavior.

- If a function view sets its `provide_automatic_options` attribute to true while the global default is false, its rule must include `OPTIONS` and use Flask's automatic response.
- If a class-based view sets its `provide_automatic_options` attribute to true while the global default is false, its rule must include `OPTIONS` and use Flask's automatic response.
- Explicit false values must continue to disable automatic handling, and a route that handles `OPTIONS` itself must continue to dispatch to that view.

Keep the existing `add_url_rule`, decorator, function-view, and class-based
view APIs intact. The relevant upstream coverage is in `tests/test_basic.py`
and `tests/test_views.py`; some assertions in those files describe behavior
that was corrected by the issue fix.
