# Correct IndexedSet slicing after removals

`IndexedSet` advertises list-like indexing and slicing, but slice bounds are
currently translated into the backing list's index space even though slicing
iterates the already compacted, dead-slot-free sequence. Correct the behavior
without changing the library's established negative-step semantics, and add a
focused standard-library regression test.

The deliverables are:

1. IndexedSet slicing after removals must interpret positive and negative start and stop bounds in the apparent, dead-slot-free index space.
2. For positive slice steps after removals, IndexedSet slicing must return the same items as slicing a list of the set's current contents, and each slice result must remain an IndexedSet.
3. Add a standard-library unittest regression artifact at `tests/test_indexed_slice_regression.py` that covers post-removal slice bounds and agreement with list slicing.
