# Preserve `CliRunner` stream lifecycles

`CliRunner.invoke` can close temporary I/O objects in an unsafe order, leaving
buffers owned by the runner unusable and causing later invocations or logging
handlers to fail with `ValueError: I/O operation on closed file`. Implement an
upstream-compatible fix in this complete Click checkout.

1. Closing one of Click's named text wrappers must leave the binary buffer it was given open and usable, including when multiple wrappers share that buffer.
2. Garbage collection and finalization of `CliRunner`'s temporary streams must leave `StreamMixer`-owned stdout, stderr, and mixed-output buffers readable; repeated invocations involving logging, threads, or exceptions must continue to restore process streams and isolate output.

Use the repository's existing pytest framework for verification. Keep the
public API and all unrelated behavior compatible with the pre-existing suite.
