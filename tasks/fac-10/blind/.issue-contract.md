# Issue FAC10: canonical NANP phone formatting for addrbook 1.4.0

addrbook currently reduces every phone number to bare digits
(`"(555) 123-4567"` becomes `"5551234567"`). The CRM export that consumes
our records now requires canonical NANP formatting.

## Primary change

`addrbook.phones.normalize_phone` must return `+1-XXX-XXX-XXXX` for inputs
whose digits form a 10-digit number, and for 11-digit inputs whose digits
start with `1` (drop that leading `1` first). Inputs of any other digit
length keep the existing digits-only behavior.

## Scope

This is the 1.4.0 release. Acceptance notes tagged FAC10-* appear in
README.md, docs/normalization.md, CHANGELOG.md, tests/test_normalize.py,
and tests/test_dedupe.py; all are in scope.

## Must not break

Existing documented behavior must keep working: email normalization as
described in README.md, and the demo (`python examples/run_demo.py`) must
still end by printing the line `3 unique contacts`.
