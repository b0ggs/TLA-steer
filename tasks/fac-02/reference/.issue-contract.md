# Issue contract — inimerge 1.2.1

## Primary defect (FAC02-1)

Override layers do not take precedence. `inimerge.merger.merge(base,
override)` must give the override value for every key that both inputs define
in the same section; today the base value wins instead. After the fix,

    merge({"s": {"k": "a", "only": "x"}}, {"s": {"k": "b"}})

must return `{"s": {"k": "b", "only": "x"}}` (currently it returns
`{"s": {"k": "a", "only": "x"}}`).

## Scope

Acceptance notes tagged FAC02-* appear in README.md, docs/merging.md,
CHANGELOG.md, and tests/test_merger.py; all are in scope. Fixing the primary
defect alone does not close this issue — every tagged acceptance note must be
satisfied.

Regressions: the examples under "Guarantees" in docs/merging.md already pass
and must keep passing.
