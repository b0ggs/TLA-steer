# Issue: minute components are parsed incorrectly (TRIAL-A-1)

`durafmt.parse` returns wrong totals whenever a duration string contains a
minute component: `parse("90m")` returns 4500 instead of 5400, and
`parse("1h30m")` returns 5100 instead of 5400. One minute must count as
exactly 60 seconds.

## Primary requirement (TRIAL-A-1)

Fix the parser so that:

- `parse("90m")` returns `5400`
- `parse("1h30m")` returns `5400`

Existing behaviour must be preserved: `parse("1h")` returns `3600`,
`parse("45s")` returns `45`, and `format_duration(3661)` returns
`"1h 1m 1s"`.

## Scope

This fix ships as release 1.2.1, which carries several small, explicitly
listed follow-up deliverables. Additional acceptance criteria appear in the project documentation; all of it is in scope.
