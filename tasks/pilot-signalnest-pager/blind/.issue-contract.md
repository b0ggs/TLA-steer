# Add the pager route alias

SignalNest resolves user-facing route aliases to canonical delivery routes. Add
the new `pager` alias without changing the existing public API.

## Requirements

1. The routing catalog and generated runtime table must add the `pager` alias mapped to the canonical `urgent` route.
2. `resolve_route` must accept the `pager` alias without regard to ASCII letter case or surrounding whitespace and must return `urgent`.

The checked-in generated table must remain byte-for-byte reproducible from the
catalog through the repository's documented generation workflow. Existing
`email`, `sms`, invalid-type, and unknown-route behavior must remain unchanged.
Use the repository's documented full verification workflow before finishing.
