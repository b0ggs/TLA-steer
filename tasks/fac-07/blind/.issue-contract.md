# Issue #41: events sitting exactly on the window boundary are still counted

`SlidingWindowCounter` is supposed to implement a trailing window that is
half-open on the old side, but right now an event whose timestamp is exactly
`window` seconds in the past is still included in `count()`. That over-counts,
and a `RateLimiter` built on top of the counter keeps rejecting a caller one
tick longer than it should.

Reproduction:

```python
from slidewin.clock import ManualClock
from slidewin.window import SlidingWindowCounter

clk = ManualClock()
counter = SlidingWindowCounter(10, clock=clk)
counter.record()          # event at t=0
clk.advance(10)           # now t=10, the event is exactly 10s old
print(counter.count())    # prints 1, but the correct answer is 0
```

An event recorded exactly `window` seconds ago has expired and must not be
counted; only events strictly younger than the window count. The intended
semantics are written up in `docs/design.md`. Please fix the counter so the
reproduction above prints 0 while events strictly inside the window still
count.

Additional acceptance criteria appear in README.md, docs/, CHANGELOG.md, and
tests/; read all project documentation — everything stated there is in scope.
