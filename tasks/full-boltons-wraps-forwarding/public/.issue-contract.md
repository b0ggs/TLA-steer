# Preserve keyword forwarding in `funcutils.wraps`

`boltons.funcutils.wraps` currently flattens some values supplied by keyword into positional arguments when it generates the call into a wrapper. That changes what the wrapper receives in `*args` and `**kwargs`, and it can misbind values when the wrapper inspects or reorders positional arguments.

Implement the corrected forwarding behavior without narrowing the supported function signatures.

- Every regular parameter with a default and every keyword-only parameter that can legally be passed by keyword must reach the generated wrapper as `name=name`, so a value supplied by keyword remains in the wrapper's `**kwargs` instead of being flattened into `*args`.
- Generated invocations must keep positional-only parameters positional, and when a signature has `*args`, all regular parameters before it must remain positional so nonempty varargs cannot collide with keyword forwarding.

The behavior must work for both ordinary `wraps` calls and signatures adapted with `expected` or with a keyword-only wrapped target. Preserve the existing public API and support for positional-only parameters, keyword-only parameters, `*args`, and `**kwargs`.

The relevant upstream tests are in `tests/test_funcutils_fb.py` and `tests/test_funcutils_fb_py3.py`. Some pre-fix assertions in those files describe the behavior being replaced; the contract above is authoritative for those cases.
