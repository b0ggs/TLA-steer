# taskcheck

`taskcheck.py` is a Python-standard-library-only validator and integrity tool
for portable coding-evaluation tasks. It has no dependency on MDs_EVAL. Its
public interfaces are versioned as **task-layout-v2** and **check-result-v2**.

## task-layout-v2

Each task is a directory whose name matches `[a-z0-9-]{1,40}`:

```
<task-id>/
  public/.issue-contract.md   # subject input; CODER.md is forbidden
  check.py                    # private checker
  reference/                  # complete correct tree
  blind/                      # complete contract-only solution; no CODER.md
  blind.provenance.json
  requirements.json
  task-meta.json              # optional
  manifest.json               # generated by admit
```

`blind.provenance.json` has exactly `solver_agent`, `timestamp`, and
`input_tree_sha256`. The tree digest is SHA-256 of the UTF-8 concatenation of
one line per file, sorted by POSIX relative path:
`<relative-path>\t<file-sha256>\n`.

`requirements.json` maps every checker requirement key to:

```json
{"R1":{"target_paths":["path/in/final/tree"],"omission_probe":{"type":"path_absent","path":"path/in/final/tree"}}}
```

The other probe form is
`{"type":"text_absent","path":"file","text":"required text"}`. A missing
path fires either probe. Admission requires every probe to fire on `public/`
and not fire on `reference/`, and every target path to exist in `reference/`.
Optional `task-meta.json` has `salience` (`enumerated`, `pointer`, or `none`)
and `parent_task_id` (a task id or null); defaults are `enumerated` and null.

Junk, bytecode, nested Git metadata, and symlinks are rejected. `manifest.json`
records all other task-file hashes, metadata, verbatim requirements, gate
results, and creation time. It is generated, never author-supplied.

## check-result-v2

Run `check.py WORKSPACE`; its working directory is the directory containing the
checker. It must use only the Python standard library, must not write to the
workspace, and must not inspect or assert on `CODER.md`. Its last stdout line is:

```json
{"requirements":{"R1":true},"regressions":{"G1":true},"resolved":true}
```

Values are booleans. For rolling compatibility, a value shaped as
`{"passed": true, ...}` is normalized to its `passed` boolean. `resolved` must
equal the conjunction of all normalized requirement and regression values.
Admission proves arm neutrality by comparing output with and without a
nonempty sentinel `CODER.md`, and proves reference determinism by two
byte-identical JSON results.

## Commands and ledgers

```
python3 tooling/taskcheck.py admit TASK [--ledger PATH] [--exposures PATH]
python3 tooling/taskcheck.py verify TASK [--ledger PATH] [--exposures PATH]
python3 tooling/taskcheck.py batch admit TASKS_DIR [--ledger PATH] [--exposures PATH]
python3 tooling/taskcheck.py batch verify TASKS_DIR [--ledger PATH] [--exposures PATH]
```

Defaults are `ledger.jsonl` and `exposures.jsonl` beside the task directories.
Every successful admission appends a canonical chained ledger row and creates
a Git commit named `admit: <task-id>`. Re-admission is allowed until any event
for that task appears in `exposures.jsonl`. Verification checks every task file,
the manifest anchor, the full ledger chain, and ledger-known deletions. Batch
mode considers every direct child directory containing `check.py`, regardless
of its name prefix, and fails if any selected task fails.

Run the standalone suite with:

```
python3 -m unittest discover -s tooling
```
